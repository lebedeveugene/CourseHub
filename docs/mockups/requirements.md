
# Вимоги до проєкту CourseHub

## 1. Призначення

CourseHub — вебзастосунок для організації онлайн-навчання. Платформа призначена для перегляду навчальних курсів, отримання інформації про їхній зміст, ознайомлення з уроками та реєстрації студентів на обрані курси.

Метою проєкту є створення зручного вебсервісу, який забезпечує доступ до навчальних матеріалів і дозволяє керувати записами студентів на курси.

## 2. Ролі користувачів

- Відвідувач — перегляд головної сторінки, пошук курсів, ознайомлення з описом і програмою навчання.
- Студент — реєстрація, запис на курси, перегляд доступних уроків і власних записів.
- Адміністратор — створення, редагування та видалення курсів і уроків, керування записами студентів.

## 3. Сутності предметної області

| Сутність | Атрибути | Призначення |
|---|---|---|
| Course | id, title, description, category, level, duration, created_at | Інформація про навчальний курс |
| Lesson | id, course_id, title, content, position, duration | Урок, що належить певному курсу |
| Student | id, full_name, email, password_hash, created_at | Дані зареєстрованого студента |
| Enrollment | id, course_id, student_id, enrolled_at, status | Інформація про запис студента на курс |

## 4. Зв'язки між сутностями

- Course 1 — ∞ Lesson: один курс містить багато уроків, кожен урок належить одному курсу.
- Course 1 — ∞ Enrollment: на один курс можуть записатися багато студентів.
- Student 1 — ∞ Enrollment: один студент може мати декілька записів на курси.
- Student ∞ — ∞ Course: зв'язок багато до багатьох реалізується через сутність Enrollment.

Для зберігання інформації планується використання реляційної бази даних MySQL. Ідентифікатори id виступають первинними ключами, а поля course_id і student_id використовуються для встановлення зв'язків між таблицями.

## 5. Сторінки вебзастосунку

1. `/` — головна сторінка з описом платформи та популярними курсами.
2. `/courses` — каталог курсів із пошуком і фільтрацією.
3. `/courses/:id` — сторінка окремого курсу з описом і переліком уроків.
4. `/enroll` — форма запису студента на обраний курс.
5. `/profile` — особистий кабінет студента зі списком його курсів.

## 6. Функціональні вимоги

F1. Система повинна забезпечувати перегляд каталогу навчальних курсів.

F2. Користувач повинен мати можливість знаходити курси за назвою та фільтрувати їх за категорією і рівнем складності без перезавантаження сторінки.

F3. Дані курсів та уроків повинні завантажуватися асинхронно із сервера.

F4. Для кожного курсу повинні відображатися назва, опис, категорія, рівень складності, тривалість та перелік уроків.

F5. Форма запису на курс повинна містити поля імені, електронної пошти та вибору курсу.

F6. Під час надсилання форми повинна виконуватися валідація: обов'язкові поля не можуть бути порожніми, ім'я повинно містити щонайменше два символи, а адреса електронної пошти повинна мати коректний формат.

F7. Система повинна зберігати інформацію про записи студентів на курси.

F8. Адміністратор повинен мати можливість додавати, редагувати та видаляти курси й уроки.

## 7. Нефункціональні вимоги

N1. Інтерфейс повинен бути адаптивним і коректно відображатися на екранах шириною від 360 px.

N2. Навігація між основними розділами повинна бути зрозумілою та доступною з головної сторінки.

N3. Цільовий показник Lighthouse Performance — не менше 85 балів.

N4. Вебзастосунок повинен підтримувати актуальні версії сучасних браузерів.

N5. Дані користувачів повинні оброблятися безпечно, паролі не повинні зберігатися у відкритому вигляді.

## 8. Заплановані ресурси API

- `GET /api/courses` — отримання списку курсів.
- `GET /api/courses/:id` — отримання інформації про курс.
- `GET /api/courses/:id/lessons` — отримання уроків курсу.
- `POST /api/enrollments` — створення запису студента на курс.

## 9. План розвитку проєкту

На першому етапі створюються документація, макети інтерфейсу, структура каталогів та репозиторій GitHub. Під час наступних лабораторних робіт буде реалізовано HTML-розмітку, стилі CSS, клієнтську логіку JavaScript, серверну частину та роботу з базою даних.

Проєкт розроблятиметься поетапно із застосуванням системи контролю версій Git.
